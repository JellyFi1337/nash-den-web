# Устройство и требования, версия 2.0

Действующее устройство «Нашего дня» после секций 27–37. Это требования, а не запросы выполненных работ. История — [PROGRESS.md](PROGRESS.md), решения — [DECISIONS.md](DECISIONS.md). [V2_PLAN.md](V2_PLAN.md) сохранён; финальная приёмка и выпуск 2.0 — его секция 38. Заголовок документа не меняет номер пакета в `pyproject.toml`.

## A1. Назначение и границы

Закрытый сайт команды: день, люди, цели, общественный проект и недельные итоги. Кураторы участвуют наравне с участниками. Настройки по умолчанию: поток 21.09–22.11.2026, третья и последняя ступень с 26.09. Шапка показывает день ступени (`web/stage.py`), календарь и недели считаются от начала потока.

Сайт показывает факты и слова людей без оценок, мест и рейтингов. Отсутствие данных не означает отсутствие действия. Сводку составляет нейросеть вне сайта; владелец проверяет и публикует её пакет. Самостоятельного вызова API нейросети нет.

Неизменные ограничения: бот отправляет только в личку; таблица читается одним GET xlsx; частные имена/тексты и адрес таблицы не попадают в код, тесты, документы и отчёты агента; бренд не перерисовывается и не перекрашивается; эталоны не удаляются и не переименовываются. Агент не выполняет Git и не добавляет зависимости Python/JS. Полные правила — [CONTRIBUTING.md](../CONTRIBUTING.md).

## A2. Стек

Python 3.12, Django 5.2, PostgreSQL 17, aiogram 3; шаблоны Django, CSS, ES-модули без сборщика и сторонних JS-библиотек. Зависимости фиксирует `uv.lock`, список — `pyproject.toml`. Продакшен: Gunicorn, WhiteNoise с манифестом, Caddy, сервис копий. Состав образов — `docker/`, сервисов — `compose*.yaml`.

## A4. Среда, время и данные

Windows 11, PowerShell, Docker Desktop; путь проекта содержит кириллицу и лежит в OneDrive. Python выполняется только в контейнерах через `dev.ps1`; на Linux соответствующие цели есть в Makefile. Исходники и примеры смонтированы в разработке, media — том `/app/media`, `private/` — только для чтения. Рабочий проект Compose — `nash-den`.

```powershell
.\dev.ps1 up
.\dev.ps1 check
.\dev.ps1 manage daycode
.\dev.ps1 logs
```

`up` создаёт отсутствующий `.env` из образца. `check`: ruff check, ruff format --check, pytest, Django check, makemigrations --check --dry-run. `audit` отдельно проверяет пакеты образа с доступом к сети. `smoke` не создаёт код дня, но проверка входа оставляет попытку и сессию. Ловушки среды перечислены в CONTRIBUTING, раздел 3.

Пароль `.env` применяется PostgreSQL при создании тома. Для базы с данными верните прежний пароль либо измените его в самой PostgreSQL и согласуйте настройки; не удаляйте том.

### A4.1. Режимы данных

`demo` (синоним `seed`) — `seed_demo --reset`: вымышленные люди с is_demo, сообщения, опубликованные отчёты и примеры снимков. `real` — `load_private --reset --reports`, `apply_chats_config`, `sync_sheet`: состав и все доступные файлы отчётов из `private/`, затем разрешённый GET таблицы. Расписание загружается отдельно командой `load_schedule`.

Режимы не смешиваются. Сброс удаляет данные команды; точный состав и счётчики возвращает `team/services.py`. Пользователи Django и настройки сохраняются. До удаления — сводка и копия `before-reset-*.dump`, если доступен pg_dump. Невосстановимые сообщения Telegram и опубликованные отчёты вне `private/reports/` требуют точного `--confirm-delete=N`; без него отказ. `--force` снимает ограничение DEBUG, но не заменяет подтверждение. Агент может подтверждать только свои временные демо-данные текущей секции; настоящие накопленные данные требуют стенда A5. Рабочая среда остаётся в real. Файлы — [INITIAL_DATA.md](INITIAL_DATA.md).

### A4.2. Время

Текущий момент — только `core.time.now()`. День сайта меняется в rollover_time (05:00 по Москве), вечер — evening_from (16:00). Окно дня сайта `[Д 05:00, Д+1 05:00)`, выгрузки `[Д 00:00, Д+1 05:00)`: ночные часы перекрываются намеренно. Средние ночных итогов допускают время больше 24:00. Расписание использует календарную дату; 00:00–05:00 подписывается датой, не ложным «сегодня». Браузер получает серверную опору `motion-boot` и пояс сайта.

## A5. Изолированный стек для проверок

Для смены режимов, публикации, массовых попыток и отказов используйте отдельный проект, порт и новые тома; при сборке — отдельный тег. Не используйте чужие старые проверочные тома. Бот не запускается, внешние настройки пустые. Override хранится во временной папке; относительные пути разрешаются от первого `compose.yaml`:

```yaml
services:
  web:
    image: nashden-web
    ports: ["127.0.0.1:8011:8000"]
    environment:
      DJANGO_SETTINGS_MODULE: config.settings.dev
      TELEGRAM_BOT_TOKEN: ""
      TELEGRAM_BOT_USERNAME: ""
      TELEGRAM_OWNER_ID: ""
      CODE_BROADCAST: "0"
      CHATS_CONFIG: /app/no-chats.toml
      SHEET_URL: ""
    volumes:
      - ./src:/app/src:ro
      - ./docs/examples:/app/docs/examples:ro
    command: ["python", "/app/src/manage.py", "runserver", "0.0.0.0:8000"]
  bot:
    profiles: ["never"]
```

Указанный образ должен содержать зависимости разработки; `--no-build` не пересобирает рабочий тег. Запускаются только db и web:

```powershell
docker compose -p nashden-check -f compose.yaml -f "<override>" up -d --no-build --wait db web
docker compose -p nashden-check -f compose.yaml -f "<override>" exec web python /app/src/manage.py seed_demo --reset
```

Для real отдельной базы — `load_private --reset --reports`; источник остаётся только для чтения. Продакшен — `compose.local-prod.yaml`, `-p nashden-localprod`, собственный тег и override с пустыми внешними настройками, loopback:8080. До проверки зафиксируйте существующие тома. После неё `down`; `down -v` допустим только для своих новых временных томов после проверки имени проекта. Рабочие и прежние тома владельца сохраняются. Подробности — [DEPLOY.md](DEPLOY.md#13-проверка-на-windows-без-сервера).

## A7. Доступ

### A7.1. Код и сессии

Код `СЛОВО2026+N`: год дня сайта, N=1–99, secrets, без повторения семи предыдущих кодов. Проверка нормализует регистр, ё/е и знаки; сравнивает SHA-256 за постоянное время. Пять ошибок за 15 минут с адреса — пауза 15 минут, IPv6 по /64. Больше 30 неверных кодов за 15 минут на весь сайт — общая пауза входа без сессии; действующие сессии работают. Админка имеет личный лимит неверных паролей.

Сессия хранит дату/ревизию кода; смена суток или ревизии требует нового входа. Успешный вход меняет ключ сессии. POST /exit/ очищает доступ; возврат только на относительный адрес своего сайта.

### A7.2. Шлюз и JSON

Открыты /enter/, /enter/telegram/, /health/, /robots.txt, /logo/, статика и путь админки с собственной авторизацией. Остальное, включая media, закрыто. Без доступа HTML получает 302 на вход; запрос с Accept: application/json — 401 `{"error":"gate","new_day":…}`. API-клиент обязан отправлять Accept и обрабатывать 401.

Telegram-вход проверяет подпись initData, срок и активного человека. В текущем HTTP-развёртывании код берут в личке и открывают ссылку браузером; Mini App требует HTTPS.

### A7.3. Права и файлы

Суперпользователь управляет данными. Кураторы: view/change Day, TimelineEvent, Achievement, Project, ChecklistItem, Decision, OpenQuestion; только view Member, Goal, Entry; без add/delete. Коды, попытки, контакты, сообщения, отчёты и настройки закрыты. /logo/ открыт до входа, без загруженного файла перенаправляет на статический знак. Media проверяет путь. core/images.py уменьшает JPEG/PNG/WebP до 640px по большей стороне; лимит Pillow — 40 млн пикселей. Неподдерживаемый формат или ошибка чтения оставляют файл без перекодирования.

Зависимые блоки без проекта/отчёта/снимка скрыты; полезные пустые состояния и защищённая подпись достижений сохранены. Desktop-сетки используют :has(), телефон сохраняет порядок.

Пульс без живого источника берёт latest_report_marks и показывает дату отчёта, приглушённые числа без празднования, искр и всплывающих событий. Это не сегодняшние отметки. Без отчёта — состояние без источника. Незавершённое сегодня не обрывает серию; средние без сегодняшних данных подписаны датой последнего отчёта.

Ритм: до 14 опубликованных дат плюс сегодня при живых отметках. x — отчёта нет, 0 — в опубликованном дне итога нет; неизвестный процент не выдумывается. При менее трёх отчётах — подпись начала данных. Средние шкал активной команды — один агрегатный запрос; пропуски разрывают линии.

Поиск: два запроса при прогретом SiteConfig, payload опубликованного и Entry report/admin за эти даты; Python-поиск, casefold/ё→е/пробелы. Приоритет образа и сводки, затем остальных блоков, внутри приоритета новые дни выше. Части отрывка экранированы до `<mark class="hl">`. RawMessage и notes не ищутся. Неделя: восемь запросов без стоимости настроек/шлюза (восьмой — опубликованная «Неделя словами»), независимо от людей/дней. Летопись (`web/archive.py`) и летопись отделов читают опубликованные пакеты одним запросом; число запросов не растёт с днями, неделями и людьми.

## A10. Бот

Long polling; отправки только через tgbot/sending.py с проверкой личного чата. Групповые обработчики сохраняют молча, но действующее развёртывание — только личка (044). Активный участник после однозначной привязки получает код по /start, /code или сообщению: отдельный блок кода, ссылка SITE_URL, срок, без кнопки под сообщением. CODE_BROADCAST по умолчанию false. CodeRequest хранит команду обращения без тела.

Владелец в личке: /help, /chats, /people, /status, /visits, /export, /week, файлы .json/.txt/.zip и подтверждение публикации. Файл распознаётся по содержимому: пакет отчёта, «Неделя словами» (публикация отдельной кнопкой), добавки расписания `{"events": [...]}` или `result.json` Telegram Desktop (импорт истории). Команды управления: runbot, apply_chats_config, export_chats, maintain. Тик обслуживает код/доставку/сессии/таблицу; повторы доставки с паузой до часа. Тик старше пяти минут завершает процесс для restart-policy; нездоровье само по себе не перезапускает живой контейнер. Без бота maintain запускается расписанием сервера. Настройка — [BOT_SETUP.md](BOT_SETUP.md), процесс — [OPERATIONS.md](OPERATIONS.md).

## A11. Сообщения, выгрузка, отчёт

### A11.1. Сохранение

journal/services сохраняет сообщение/правку идемпотентно по чат/сообщение. Связывает по Telegram ID, затем однозначному username; неизвестный остаётся контактом. Медиа представлены подписью, не расшифровываются. Старую историю Telegram сам не отдаёт.

### A11.2. Темы

CHATS_CONFIG=/app/private/chats.toml; роли/export/ai/имена txt — [CHATS_CONFIG.md](CHATS_CONFIG.md), вымышленный образец chats.example.toml. Journal не более одной темы; отсутствие файла допустимо в личке. Страницы читают Topic.role, не частный файл.

### A11.3. Отметки «на связи»

До публикации — сообщения активного человека из journal длиной не меньше 40 символов. Первое подходящее до 16:00 — утро; после 16:00 — итог. Ответ на собственную утреннюю запись — итог и раньше 16:00. Первое время каждого вида.

Ночью 00:00–05:00 сообщение — итог Д−1, если там было утро и ещё нет итога; иначе утро нового дня. В ночном хвосте окна Д сообщение закрывает итог Д только при его незакрытом утре. Чистый расчёт compute_marks; day_marks опубликованного дня — report/admin, иначе живые сообщения. marks_source: report, chat (journal с сохранёнными сообщениями), none. Датированный fallback последнего отчёта на главной этих правил не меняет.

### A11.4. Выгрузка

/export без даты — вчера; сегодня/вчера, дата, диапазон. Архив: txt тем export=true и 00-instrukciya.md с инструкцией, файлами, активным составом, фактами среза/окна/отметок, проектом и пятью блоками образца. «ФАКТЫ» добавляют последнее сохранённое сообщение окна и командные числа окна (сообщений, тем, людей команды, ответов другому человеку). Если сообщений темы journal за окно в базе нет, таблица отметок не выводится — вместо «нет сообщения в выгрузке» у всех строка «Отметки не посчитаны». Дата в хэштеге (#утро_7_10) или в начале записи, не совпадающая с днём, — строка «Дата в тексте не совпадает с днём (проверить)»; отметки по-прежнему считаются по A11.3. /week [N] — набор для «Недели словами» из опубликованных дней недели. Отсутствие сообщения — отсутствие в выгрузке, не оценка. Чужая подпись требует проверки. Без сообщений может быть только инструкция. Архив больше 45 МБ делится на последовательные части для склейки. Формат и смысл инструкции — [REPORT_FORMAT.md](REPORT_FORMAT.md).

### A11.5. Приём и публикация

nash-den.report version=2: den/lyudi обязательны, proekt/golosa/svyazi необязательны; необязательное `den.chat` — текст для общего чата. Порядок частей свободный; повтор заменяет часть в одной строке DayReport. Дословные цитаты сверяются с сообщениями автора за окно дня, расхождение — предупреждение (REPORT_FORMAT 6). nash-den.week version=1 — «Неделя словами», черновик до явной публикации (REPORT_FORMAT 9). Intake: 20 файлов, 5 МБ текста на файл, 20 МБ всего; повреждение/не UTF-8 — понятная ошибка. Проверка нормализует типы, разрешает человека по ключу/имени, сохраняет warnings/notes для владельца. Транзакционная публикация отменяет вклад прежнего отчёта и применяет новый, ручные правки сохраняются; повтор идемпотентен. Нет автоматической публикации. Код journal/report; docs/examples/report-example.json совпадает с src/apps/journal/report/example.json.

### A11.6. Импорт истории

manage.py import_chat_export <result.json> (или файл боту) читает JSON Telegram Desktop целиком: все темы по цепочке ответов, настоящие номера сообщений, текст из `rich_message`, медиа подписью, правки. Повтор и сообщение, уже сохранённое ботом, обновляют одну строку. Автор — по Telegram ID участника, иначе по однозначному совпадению имени с полным/коротким именем и «именами в чате»; Telegram ID при этом не привязывается. После импорта записи опубликованных отчётов связываются с исходными сообщениями темы journal по человеку и минуте. Пакетная запись: число запросов не зависит от числа сообщений. Старый txt одной темы — с `--chat` и `--thread`. Импортированные сообщения имеют настоящие номера, поэтому сброс режимов считает их невосстановимыми и требует `--confirm-delete=N`. Частные выгрузки вне Git; разрушающие проверки только A5.

### A11.7. Блоки

В модели — данные для периодов: Day, Entry, GoalStep, TimelineEvent, Achievement, TaskDay, ProjectUpdate, решения/вопросы. Голоса, связи, погода, факты, отделы, риски и следующий шаг остаются в payload. report_blocks и report_blocks_from_payload нормализуют их; второй без запросов. Notes не показываются посетителям и не ищутся.

## A12. Таблица и банк штрафов

sheet/client fetch_book: один GET xlsx до 20 МБ, openpyxl в памяти, без иных обращений/Google API/gspread/записи. Шесть известных вкладок, столбцы по заголовкам; последний удачный снимок сохраняется при сбое. Поля — [SHEET.md](SHEET.md); телефон, адрес, семья и точный возраст не хранятся. Цели синхронизируются с Goal, исчезнувшие неактивны. Недели от начала потока, последняя может быть неполной. Анкета/вклад/вовлечение/коуч-сессии — снимок, запись на сессию только в таблице. SHEET_TTL=900 — свежесть; автоматическое чтение не чаще часа, ручное sync_sheet.

Банк растёт от моментов «не в слове», деньги уходят в никуда; не достижение и не накопление на проект. Сумма — строка «Банк», иначе сумма дней. Порог/ставки в SiteConfig; у 80% предупреждение, после порога новая ставка. Сайт не начисляет и не записывает штрафы.

web/fines без базы/сети: прогноз, виды, недели, чистые дни, путь. Прогноз — остаток / средняя сумма существующих дат последних семи дней до сегодня, округление вверх; пропуск не ноль, будущие даты исключены. При нулевом темпе/за концом потока отдельная подпись; после порога прогноз не нужен. Путь суммирует дни и может отличаться от строки «Банк». Главная краткая, подробности в статистике.

## A13. Безопасность

HTML private/no-store и noindex/nofollow, robots запрещает индексацию. CSRF включён. CSP: свои скрипты/шрифты, на входе ещё telegram.org; img-src self data: без blob:, connect-src self, без inline-скриптов/style-блоков, style-атрибуты разрешены. Продакшен frame-ancestors вместо X-Frame-Options для Telegram; HTTPS-переход делает Caddy.

Текущий серверный режим HTTP по IP (043): код/cookie без шифрования; путь HTTPS — DEPLOY. Secure-cookie/HSTS соответствуют стеку. Clipboard/Share требуют проверки доступности; HTTP по IP не secure context, localhost/127.0.0.1 — secure context. Логи stdout без тел запросов, cookie, кодов, токенов, initData и частных текстов. .env/private/chats не входят в образ. Ошибки — свои шаблоны; 500 без запросов контекста шапки, connect_timeout базы 3 с.

## A14. Качество

Тесты config.settings.test, отдельная база, вымышленные данные, сеть подменена. Сервисы/селекторы/расчёты/права и ошибки проверяются на границах. Образцы совпадают; запросы не растут с размером команды/периода. Проверки не ослабляются ради зелёного результата. После изменения dev.ps1 check.

Для интерфейса demo/real, 390/1280, обе темы/три палитры; границы 320/768/1440, текст 3, спокойное/системное reduced-motion; пустая база/нет снимка/будущее. Продакшен: отдельная сборка, collectstatic, обход страниц, ноль 404 статики/ошибок консоли. Непроверенное перечисляется честно; Git выполняет владелец.
