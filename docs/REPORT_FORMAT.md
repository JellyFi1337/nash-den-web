# Отчёт дня: формат обмена с нейросетью

Сайт не составляет смысловую сводку сообщений сам; программа считает только предусмотренные отметки и факты выгрузки. Цепочка обработки отчёта такая:

1. **Бот** умеет молча сохранять сообщения чатов и тем, куда добавлен. Текущее развёртывание — только личка; историю владелец даёт нейросети выгрузкой Telegram Desktop (OPERATIONS.md).
2. **Владелец** командой `/export` получает от бота архив: txt-файлы тем за день и файл с инструкцией для нейросети.
3. **Владелец** вручную отдаёт эти файлы нейросети (в её чате или приложении).
4. **Нейросеть** возвращает **пакет отчёта** — от двух до пяти файлов JSON по этому документу. Владелец ждёт.
5. **Владелец** добавляет файлы на сайт: отправляет их боту (по одному или архивом) либо загружает на странице «Загрузить отчёт» в админке. Сайт проверяет каждый файл, показывает сводку и после подтверждения публикует.

Формат называется `nash-den.report`, версия `2`. Образец пакета — `docs/examples/report-example.json` (данные вымышленные).

Живые данные, которые команда и кураторы ведут сами, приходят не отсюда, а из таблицы: `docs/SHEET.md`. Отчёт — про день в чате; таблица — про цели, неделю и дисциплину.

## 1. Набор для нейросети

Архив `export-ГГГГ-ММ-ДД.zip`, который бот присылает владельцу:

```
export-2026-09-29.zip
├─ 00-instrukciya.md        инструкция, состав команды, проект, описание формата и образец
├─ konteksty-itogi.txt      тема с ролью journal
├─ op.txt                   темы с ролью project
├─ op-lidery.txt
├─ otdel-smi.txt
├─ insayty.txt              тема с ролью task
└─ …                        остальные темы с export = true
```

Формат txt-файлов описан в `docs/CHATS_CONFIG.md`: строка `[29.09.2026 06:14] Фамилия Имя: текст`.

Файл `00-instrukciya.md`:

```
# ОТЧЁТ ДНЯ · 2026-09-29 · инструкция для нейросети

## ИНСТРУКЦИЯ
<текст из раздела 5 этого документа>

## ФАЙЛЫ
konteksty-itogi.txt — утренние декларации и вечерние итоги (journal)
op.txt, op-lidery.txt, otdel-smi.txt — общественный проект (project)
insayty.txt — задание дня и инсайты (task)
Остальные файлы читай только для частей 4 и 5.

## КОМАНДА
ключ | имя в файлах | роль | цели
example_lada | Демина Лада | участник | breakthrough: Дополнительный доход +50%; creative: Событие на 10 участниц; unfinished: Закончить блок курса
example_pavel | Климов Павел | куратор | …

## ФАКТЫ
Срез выгрузки: 2026-09-30 05:00 · окно дня: 2026-09-29 00:00 — 2026-09-30 05:00
ключ | утро | итог
example_lada | 06:14 | 21:06
mark_o | 07:02 | нет сообщения в выгрузке
Итоги, отправленные не автором: 20:54 asya_k — подпись в тексте: «…» (проверить)

## ПРОЕКТ
Название: Город нового времени · срок: 2026-10-23
Открытые решения:
D12 | Переговоры с парком | vera_s | до 2026-09-30
Открытые вопросы:
Q4 | Кто обзванивает парки?
Чек-лист (не сделано):
C6 | Площадка

## ФОРМАТ ОТВЕТА
<таблицы полей из разделов 3 и 4 и образец пакета>
```

Правила набора:

- `ключ` человека — его имя пользователя Telegram строчными буквами без `@`; у кого его нет — `id` и числовой идентификатор, например `id123456789`. В отчёте человека можно назвать ключом или именем из файлов — сайт понимает оба варианта.
- В разделе «ФАЙЛЫ» перечислены темы из `chats.toml`: с `ai = true` — обязательные для разбора, остальные с `export = true` — как дополнительный материал.
- Окно дня `Д` в файлах: сообщения с 00:00 даты `Д` до времени смены суток (05:00) даты `Д+1`. Окна соседних дней перекрываются на ночные часы намеренно: к какому дню относится ночное сообщение, решает нейросеть по правилам из инструкции.
- В раздел «ПРОЕКТ» попадают только незакрытые решения, вопросы и несделанные пункты чек-листа — с номерами, по которым их можно закрыть.
- Голосовые и видео бот не расшифровывает: в файлах они видны как `[ Голосовое сообщение ]`, `[ Видеосообщение ]`.
- Раздел «ФАКТЫ» (решение 035) считает программа по правилам A11.3 плана: время среза, окно дня, по каждому активному человеку время первой утренней и вечерней отметки в теме `journal` или «нет сообщения в выгрузке», и список сообщений, похожих на итог, отправленных с чужого аккаунта (подпись в тексте не совпадает с автором). «Нет сообщения в выгрузке» не означает «не сделал»: человек мог написать в другом месте или после среза.

## 2. Пакет отчёта: из чего он состоит

Нейросеть возвращает **отдельные файлы по частям**. Так сделано потому, что один файл на 19 человек со всеми блоками нейросеть не дописывает до конца, а части строятся из разных тем чата и разными запросами.

| Файл | `part` | Обязательна | Что внутри | Где видно на сайте |
|---|---|---|---|---|
| `1-den.json` | `den` | да | образ дня, сводка, лента суток, задание, достижения | главная — блок «Главное»; страница дня — шапка и лента |
| `2-lyudi.json` | `lyudi` | да | записи людей: утро, итог, шкалы, слова дня, шаги к целям | строки людей на главной, в команде, в дне; страница человека |
| `3-proekt.json` | `proekt` | нет | подвижки проекта, решения, вопросы, отделы | страница «Проект»; блок «Проект за день» |
| `4-golosa.json` | `golosa` | нет | инсайты по заданию, разговор дня, цитаты, слова дня команды | страница дня — блок «Голоса дня» |
| `5-svyazi.json` | `svyazi` | нет | кто кого поддержал, пары «бади» | страница дня — блок «Кто кого держал»; страница человека |

Каждый файл — один объект JSON с общей шапкой:

```json
{"format": "nash-den.report", "version": 2, "part": "den", "day": "2026-09-29", "…": "блоки части"}
```

Допустим и **один файл со всеми частями** — для дня, где данных немного:

```json
{"format": "nash-den.report", "version": 2, "day": "2026-09-29",
 "parts": {"den": {}, "lyudi": {}, "proekt": {}}}
```

Правила пакета:

- Части можно присылать по одной и в любом порядке: сайт складывает их в один черновик дня. Повторно присланная часть заменяет прежнюю.
- Публикация возможна, когда в черновике есть `den` и `lyudi`. Часть, присланная после публикации, дополняет отчёт и публикуется той же кнопкой.
- `day` во всех частях одного дня совпадает. Иначе — ошибка.
- Имена полей — латиницей, тексты — на русском. Пустое значение — `null` или отсутствие поля; выдумывать содержимое нельзя.
- Человек в любой части называется ключом или именем (раздел 1).
- Тексты длиннее предела обрезаются по слову с предупреждением. Пределы указаны в таблицах.

## 3. Часть `den` — образ дня

```json
{
  "format": "nash-den.report", "version": 2, "part": "den", "day": "2026-09-29",
  "source": {"model": "model-name", "files": ["konteksty-itogi.txt", "op.txt"], "messages": 214},
  "title": "Горы, парки и первые тексты",
  "lead": "День начался на два часа раньше обычного и весь ушёл в поиск площадки.",
  "summary": "Главное за день: 2–4 предложения.",
  "bullets": ["Утро — 19 из 19, в среднем в 07:48", "«Лето в Москве» закрыто, начались переговоры с парком"],
  "weather": {"code": "sun_after_rain", "text": "после тяжёлого утра — ясно"},
  "tempo": "плотный",
  "quote": {"member": "mark_o", "text": "Поддержка — это круто", "about": "о вечернем созвоне"},
  "timeline": [
    {"time": "17:07", "kind": "turn", "title": "Площадка закрылась",
     "text": "«Лето в городе» закрыто до следующего сезона, команда проекта переключилась на парки", "members": ["vera_s"]}
  ],
  "task": {"title": "Противоположный угол матрицы",
           "essence": "Найти в себе противоположное качество и прожить день из него.",
           "done": ["example_lada", "mark_o"], "insight": "Почти все написали про страх показаться слабым."},
  "achievements": [{"text": "Отдел СМИ выпустил первые тексты и визуал", "who": ["asya_k"]}],
  "attention": [{"text": "Дата 23.10 не подтверждена площадкой", "who": []}],
  "numbers": [{"label": "сообщений в чате", "value": 214, "note": "9 тем"}],
  "chat": "🎙 Наш день · вт, 29.09 · Горы, парки и первые тексты\n\nДень начался на два часа раньше обычного…",
  "notes": ["Итог без подписи в 20:54 отнесён к asya_k по содержанию — проверьте."]
}
```

| Поле | Обязательно | Правила | Где видно |
|---|---|---|---|
| `source` | нет | `model` — чем составлен отчёт, `files` — какие файлы разобраны, `messages` — сколько сообщений учтено | в админке, в сводке проверки |
| `title` | да | образ дня, 2–6 слов, до 60 знаков, без точки в конце | крупный заголовок страницы дня |
| `lead` | нет | одно предложение о дне, до 240 знаков | под заголовком дня |
| `summary` | да | 2–4 предложения, до 600 знаков | блок «Главное» на главной и в дне |
| `bullets` | нет | 3–6 строк по 140 знаков: самое важное фактами | список под сводкой |
| `weather` | нет | `code` — одно из: `clear`, `sun_after_rain`, `clouds`, `wind`, `storm`, `fog`; `text` — до 60 знаков | плашка рядом с датой |
| `tempo` | нет | одно слово о ритме дня, до 20 знаков: «ровный», «плотный», «тихий» | плашка |
| `quote` | нет | `member`, `text` до 200 знаков без кавычек по краям, `about` до 80 знаков | цитата дня |
| `timeline` | нет | до 30 событий: `time` — `ЧЧ:ММ`; `kind` — `start`, `turn`, `win`, `call`, `question`, `finish`; `title` до 60; `text` до 240; `members` — ключи | лента суток |
| `task` | нет | `title` до 120, `essence` до 240, `done` — ключи сдавших, `insight` до 240 — общее в ответах | блок «Задание дня» |
| `achievements` | нет | до 5: `text` до 200, `who` — ключи (может быть пусто) | блок «Достижения» |
| `attention` | нет | до 5: `text` до 200 — что осталось нерешённым в деле; `who` — ключи | блок «На что смотрим» |
| `numbers` | нет | до 4 цифр о дне: `label` до 40, `value` — целое, `note` до 40; при строке «Числа окна» в «ФАКТАХ» — оттуда | цифры на странице дня |
| `chat` | нет | та же сводка обычным текстом для общего чата, до 3500 знаков; только факты пакета; эмодзи-маркеры разделов допустимы (секция 39) | блок «текст для общего чата» с кнопкой «Скопировать» внизу страницы дня |
| `notes` | нет | сомнения нейросети; на сайте не публикуются | сводка проверки и админка |

`attention` — только о деле: незакрытый вопрос, несогласованная дата, зависший контакт. Про людей («не написал», «отстаёт») там ничего быть не может.

## 4. Остальные части

### 4.1. `lyudi` — записи людей

```json
{
  "format": "nash-den.report", "version": 2, "part": "lyudi", "day": "2026-09-29",
  "people": [
    {
      "member": "example_lada",
      "morning": {
        "sent": "29.09.2026 06:14",
        "context": "Море заряжает энергией и наполняет любовью.",
        "goals": ["Прилететь в Сочи", "Сдать требования по проекту", "Урок курса"],
        "contract": "лёгкая, успешная, любящая, открытая",
        "callsign": "Плавучая"
      },
      "evening": {
        "sent": "29.09.2026 21:06",
        "context_pct": 90, "goals_pct": 90, "extra": {"бытие": 70},
        "text": "Тренер приехал поздно, тренировки начнутся завтра. Вдохновляется горами.",
        "wins": ["Сдала требования по проекту", "Договорилась о тренировке на открытой воде"],
        "unfinished": "Тренировка на открытой воде",
        "highlight": "От одной только открытости люди делают первые шаги"
      },
      "goal_steps": [{"goal": "unfinished", "text": "Урок курса запланирован"}],
      "strength": "генерирует идеи даже в дороге"
    }
  ]
}
```

| Поле | Обязательно | Правила |
|---|---|---|
| `people` | да | каждый человек — не больше одного раза; кого нет в списке, у того за день нет записей |
| `member` | да | ключ или имя из раздела «КОМАНДА» |
| `morning` | нет | объект или `null` |
| `morning.sent` | да | дата и время сообщения в точности как в квадратных скобках в файле: `ДД.ММ.ГГГГ Ч:ММ`; при нескольких сообщениях — время первого |
| `morning.context` | нет | видение дня, до 400 знаков |
| `morning.goals` | нет | до 15 строк по 160 знаков, словами человека, без нумерации |
| `morning.contract` | нет | до 200 знаков |
| `morning.callsign` | нет | качество дня: одно качество из слов самого человека, до 40 знаков |
| `evening` | нет | объект или `null` |
| `evening.sent` | да | как у утра |
| `evening.context_pct`, `goals_pct` | нет | целое 0–100 или `null`; только то, что человек назвал сам |
| `evening.extra` | нет | другие шкалы человека: `{"бытие": 50}` |
| `evening.text` | нет | итог сжато, словами автора, до 600 знаков |
| `evening.wins` | нет | до 4 строк по 160 знаков: что получилось — по фактам из его сообщения |
| `evening.unfinished` | нет | что осталось, его же словами, до 300 знаков |
| `evening.highlight` | нет | слова дня: дословная фраза человека, до 200 знаков |
| `goal_steps` | нет | шаги к целям потока: `goal` — `breakthrough`, `creative` или `unfinished`; `text` до 200 знаков |
| `strength` | нет | сильная сторона дня по фактам, до 160 знаков |

### 4.2. `proekt` — общественный проект

```json
{
  "format": "nash-den.report", "version": 2, "part": "proekt", "day": "2026-09-29",
  "pulse": "Площадка не найдена, но появилось два живых варианта.",
  "progress": [{"text": "Начаты переговоры с Люберецким парком", "who": ["vera_s"]}],
  "decisions_new": [{"title": "Смета: шатры и мебель", "owners": ["egor_m"], "due": "2026-10-02"}],
  "decisions_done": [12],
  "questions_new": ["Кто обзванивает парки?"],
  "questions_closed": [4],
  "checklist_done": [6],
  "departments": [
    {"name": "Отдел СМИ", "summary": "Собраны тексты и четыре варианта визуала",
     "done": ["Концепция «Архитектура себя»"], "next": ["Выбрать визуал"], "people": ["asya_k"]}
  ],
  "risks": [{"text": "Без площадки нельзя подтвердить дату", "level": "warn"}],
  "next_step": {"text": "Съездить в парк и посмотреть крытые площадки", "owners": ["vera_s"], "due": "2026-10-01"}
}
```

| Поле | Правила |
|---|---|
| `pulse` | одна строка о состоянии проекта, до 200 знаков |
| `progress` | до 10: `text` до 300, `who` — ключи |
| `decisions_new` | `title` до 200, `owners` — ключи, `due` — дата или `null` |
| `decisions_done`, `questions_closed`, `checklist_done` | номера из раздела «ПРОЕКТ» инструкции, без буквы |
| `questions_new` | до 10 строк по 200 знаков |
| `departments` | до 6: `name` до 60, `summary` до 240, `done` и `next` — до 5 строк по 200, `people` — ключи |
| `risks` | до 5: `text` до 200, `level` — `note` или `warn` |
| `next_step` | ближайший шаг: `text` до 200, `owners` — ключи, `due` — дата или `null` |

### 4.3. `golosa` — голоса дня

```json
{
  "format": "nash-den.report", "version": 2, "part": "golosa", "day": "2026-09-29",
  "insights": [{"member": "example_lada", "text": "Страх показаться слабой держал меня сильнее, чем усталость.",
                "about": "задание дня"}],
  "talk": {"title": "Что важнее: охват или глубина", "text": "Вечером обсуждали формат события…",
           "members": ["mark_o", "vera_s"],
           "quotes": [{"member": "vera_s", "text": "Пусть придёт меньше, но по-настоящему"}]},
  "voices": [{"member": "asya_k", "text": "Я впервые написала текст, который не стыдно показать"}],
  "words": [{"word": "опора", "count": 11}],
  "light": [{"text": "Команда проекта назвала себя черепахами, которые собирались быть пантерами", "who": ["mark_o"]}]
}
```

| Поле | Правила |
|---|---|
| `insights` | до 20: `member`, `text` до 300 знаков — дословно или почти дословно, `about` до 60 |
| `talk` | разговор дня: `title` до 60, `text` до 600, `members` — ключи, `quotes` — до 4 по 200 знаков |
| `voices` | до 6 коротких цитат дня: `member`, `text` до 200 |
| `words` | до 8 слов, которые повторялись у разных людей: `word` до 24, `count` — целое |
| `light` | до 3: светлое и смешное дня, `text` до 200, `who` — ключи |

`voices` — это разные люди: одного человека в этом списке не больше одного раза, и цитата дня из части `den` в нём не повторяется.

### 4.4. `svyazi` — связи дня

```json
{
  "format": "nash-den.report", "version": 2, "part": "svyazi", "day": "2026-09-29",
  "links": [{"from": "mark_o", "to": "example_lada", "kind": "support", "text": "Разобрал с ней страх созвона"}],
  "pairs": [{"a": "asya_k", "b": "egor_m", "text": "Вместе собрали визуал"}]
}
```

| Поле | Правила |
|---|---|
| `links` | до 40: `from` и `to` — ключи разных людей, `kind` — `support` (поддержал), `push` (подтолкнул), `thanks` (благодарность), `answer` (ответил по делу); `text` до 200 знаков |
| `pairs` | до 10: `a`, `b` — ключи, `text` до 200 знаков |

Связи берутся только из явных сообщений: ответ человеку, обращение по имени, благодарность. Догадки — нет. Сравнений «кто поддержал больше всех» на сайте нет, поэтому считать их не нужно.

## 5. Инструкция для нейросети

Этот текст бот вставляет в раздел «ИНСТРУКЦИЯ» файла `00-instrukciya.md` дословно, подставляя дату.

```
Ты составляешь отчёт дня для закрытого сайта команды. Команда проходит лидерскую программу: утром каждый пишет декларацию (контекст, цели, контракт), вечером — итоги дня. К инструкции приложены текстовые файлы с сообщениями за день из тем чата; какие файлы для чего — в разделе «ФАЙЛЫ». Строка файла: [дата время] Фамилия Имя: текст. Ниже — состав команды и состояние общего проекта.

Верни ПЯТЬ файлов JSON за день {ДАТА} в формате nash-den.report версии 2, по одному на часть:
1-den.json (part den) — образ дня
2-lyudi.json (part lyudi) — записи людей
3-proekt.json (part proekt) — общественный проект
4-golosa.json (part golosa) — инсайты и цитаты
5-svyazi.json (part svyazi) — кто кого поддержал
Если для части нет данных — этот файл не присылай и скажи одной строкой, почему. Части den и lyudi обязательны. Каждый файл — отдельный блок кода, внутри только JSON, без текста до и после. В каждом файле есть поля format, version, part, day. Описание полей и образец даны в конце инструкции.

Порядок работы: сначала 2-lyudi.json (это самая долгая часть), затем 1-den.json, затем остальные. Если чувствуешь, что ответ обрывается, — закончи текущий файл и начни следующий отдельным сообщением.

Как разбирать сообщения
1. Утреннюю декларацию и вечерний итог человека ищи в файле с пометкой (journal). Декларация содержит контекст или видение и цели на день. Итог содержит оценку дня, обычно с процентами контекста и целей, и часто написан ответом на свою декларацию.
2. День определяй по хэштегу с датой (#утро_7_10, #вечер_7_10) или по дате в тексте сообщения, если они есть; явная опечатка в дате — не дата. Если даты нет: декларация относится к дате отправки; итог, отправленный ночью до 05:00, относится к предыдущему дню. Декларации следующего дня и итоги предыдущего дня в этот отчёт не включай.
3. В поле sent переноси дату и время сообщения в точности как в квадратных скобках в файле. Человека называй ключом из раздела «КОМАНДА».
4. Проценты бери только те, что человек назвал сам: «Контекст 80%», «К: 90», «Ц-100%», «💯» (это 100). Фразы вроде «минус 100%» в описании чувств — не шкала. Нет числа — ставь null. Другие шкалы (например «бытие») клади в extra.
5. goals — цели человека на день его словами, коротко, без нумерации. contract — качества из строки «Я сегодня…», «Я есть…», «Контракт». callsign — качество дня: одно из этих качеств, которое лучше всего отражает его день, с заглавной буквы.
6. highlight — одна дословная фраза человека из итога, которая передаёт его вывод дня. Не сочиняй и не улучшай её. wins — то, что у него получилось, по фактам из его сообщения, до четырёх коротких строк. unfinished — что, по его же словам, осталось.
7. goal_steps — только если из сообщений видно конкретное действие к одной из его целей потока (они перечислены в разделе «КОМАНДА»). strength — одна короткая фраза о том, что у человека сегодня получилось, по фактам.

Часть den
8. title — образ дня в 2–6 словах: то, чем этот день отличается от других. Не «Итоги дня» и не дата. lead — одно предложение. summary — 2–4 предложения: сколько человек вышло на связь утром и вечером, что сдвинулось в проекте, чем запомнился день. bullets — 3–6 строк с фактами и числами.
9. weather — погода дня как образ состояния команды, code из списка, text — короткое пояснение словами дня. tempo — одно слово о ритме.
10. timeline — события дня по времени из файлов тем (project) и (task): что произошло и что это изменило. Не переписывай туда утренние и вечерние записи людей — они уже в части lyudi.
11. task — задание дня из файла (task): название, суть одной фразой, кто сдал, и одно общее наблюдение по ответам. achievements — только общие достижения команды, без выдумки. attention — незакрытые вопросы дела, не людей. numbers — до четырёх командных цифр, которые видно из файлов; если в «ФАКТАХ» есть строка «Числа окна», бери их оттуда. chat — по желанию: та же сводка обычным текстом для общего чата, до 3500 знаков, только то, что уже есть в остальных полях пакета.

Части proekt, golosa, svyazi
12. proekt — из файлов (project): подвижки, новые договорённости «что — кто — срок», закрытые решения и вопросы по номерам из раздела «ПРОЕКТ», отделы (у каждого отдела своя тема), риски и ближайший шаг.
13. golosa — инсайты по заданию (файл с пометкой (task)), разговор дня, короткие цитаты разных людей, слова, которые за день повторились у нескольких человек, и одно-два светлых или смешных наблюдения.
14. svyazi — только явные случаи: ответ человеку, обращение по имени, благодарность. Ничего не додумывай; считать, кто поддержал больше всех, не нужно.

Тон и голос
- Спокойный, поддерживающий, уважительный. Команда читает отчёт сама.
- Сводку дня (title, lead, summary, bullets, timeline, task, achievements, attention, proekt, talk, light, chat) пиши голосом командного диктора: «мы», короткие фразы, начинай с факта или картинки дня, конкретика вместо общих слов — время, числа, дела. Без пафоса, канцелярита и пустых похвал; восклицательный знак — не больше одного на текст.
- Слова людей (утро, итог, highlight, quote, voices, insights, quotes разговора) — их собственные: дословно или сжато их же словами, без «улучшений».
- Никаких рейтингов и военной лексики: «лучший», «лидер дня», «герой», «штурм», «бой».
- Никаких оценок людей и сравнений между ними. Слов «провал», «не справился», «отстаёт» нет.
- Незавершённое описывай фактами и словами самого человека.
- Не пересказывай подробности о здоровье, семье и деньгах: достаточно «забота о здоровье», «семейные дела».
- Советы о лечении и здоровье в отчёт не включай.
- Не приписывай людям чувства, мотивы и слова, которых нет в сообщениях.

Если сомневаешься
- Неясно, чья запись, к какому дню она относится или как понять число — выбери самый осторожный вариант и напиши об этом одной строкой в notes части den. Текст в notes видит только владелец.
- Если у человека нет декларации или итога — ставь null. Не придумывай.

Факты
15. Раздел «ФАКТЫ» посчитан программой. Время sent бери из файлов, но наличие утра и итога сверяй с «ФАКТАМИ»; если видишь расхождение — запиши его в notes, не пересчитывай сам. «Нет сообщения в выгрузке» не превращай в оценку человека. Если там написано «Отметки не посчитаны», утро и итог бери из сообщений выгрузки. Итог, отправленный с чужого аккаунта, относи к человеку из подписи только если это ясно из текста, и упомяни в notes. Строку «Дата в тексте не совпадает с днём» проверь по сообщению и своё решение запиши в notes.

Проверь перед ответом: каждый файл разбирается как JSON; day = {ДАТА} во всех файлах; part указан верно; ключи людей — из раздела «КОМАНДА»; проценты — целые 0–100 или null; каждый человек в people встречается один раз.
```

В раздел «ФОРМАТ ОТВЕТА» бот добавляет таблицы полей из разделов 3 и 4 и образец пакета — пятью отдельными блоками кода с заголовками `1-den.json` … `5-svyazi.json`, ровно в том виде, в каком нейросеть должна ответить. Файл со всеми частями сразу (`parts`) в инструкции не показывается: сайт его принимает, но просить о нём нейросеть не нужно.

## 6. Проверка при загрузке

Проверяется каждый файл отдельно.

**Ошибки — часть отклоняется целиком:**

- это не JSON или не объект; `format` или `version` не те;
- `part` не из списка (`den`, `lyudi`, `proekt`, `golosa`, `svyazi`) и нет объекта `parts`;
- `day` не дата или в будущем; `day` не совпадает с днём уже принятых частей;
- в части `den` нет `title` или `summary`; в части `lyudi` нет `people`;
- неизвестный ключ или имя человека; человек встречается в `people` дважды;
- шкала вне 0–100 или не целое;
- неизвестный вид цели; номер решения, вопроса или пункта чек-листа, которого нет;
- в `links` `from` и `to` — один и тот же человек.

**Предупреждения — часть принимается, владелец видит список:**

- текст длиннее предела — обрезается по слову;
- `weather.code`, `timeline[].kind`, `links[].kind`, `risks[].level` не из списка — значение отбрасывается, остальное сохраняется;
- `sent` не разбирается или отстоит от `day` больше чем на сутки — запись принимается, но получает время публикации отчёта;
- сохранённое сообщение человека с таким временем не найдено — запись принимается, полный текст на сайте не показывается;
- дословная цитата (`highlight`, `quote`, `voices`, `talk.quotes`) не найдена в сообщениях автора за окно дня, а инсайт (`insights`) не совпадает с его сообщением большинством значимых слов — «Цитата не найдена в сообщениях автора за день». Сверка идёт только когда за день в базе есть сообщения (секция 39);
- за этот день уже есть опубликованный отчёт — он будет заменён;
- активного участника нет в `people`;
- эта часть уже была принята — она заменяется;
- лишние неизвестные поля — игнорируются.

Перед разбором из текста убираются обёртки вида ```` ```json … ``` ```` и всё до первой `{` и после последней `}`. Если в одном сообщении несколько блоков кода, каждый разбирается как отдельная часть.

## 7. Публикация

- Пакет хранится целиком: `DayReport.payload` — объект `{"parts": {…}}`, `DayReport.parts` — список принятых частей. На дату одна строка DayReport: статус draft либо published; новые части обновляют её.
- Публикация выполняется в одной транзакции: сначала отменяется всё, что внёс предыдущий отчёт этого дня, затем применяется новый.
- В модели переносится то, что нужно для списков и страниц за несколько дней: сводка, образ и цитата дня (`Day`), записи людей (`Entry`, `source = report`), шаги к целям, события ленты, достижения, задание дня, подвижки проекта, новые решения и вопросы, отметки о закрытии.
- Остальные блоки (`bullets`, `weather`, `tempo`, `numbers`, `attention`, `chat`, части `golosa` и `svyazi`, отделы, риски, ближайший шаг) в отдельные модели не переносятся: страницы читают их из `payload` через селектор `report_blocks(day)`. Правило: то, что нужно только для показа одного дня, остаётся в отчёте. Летопись отделов, «Голоса потока» и «Альманах» собирают эти блоки по всем опубликованным пакетам одним чтением.
- То, что внесено вручную в админке, отчёт не затирает.
- Полный текст записи на сайте берётся из сохранённого сообщения: сайт находит его по человеку, теме `journal` и времени `sent` с точностью до минуты.

## 8. Как владелец добавляет отчёт на сайт

Два равноправных способа. Оба доступны только владельцу.

**Через бота** — в личных сообщениях:

```
владелец: /export вчера
бот:      [файл export-2026-09-29.zip] Выгрузка за 29.09: 9 тем, 214 сообщений, 19 человек.

          … владелец отдаёт файлы нейросети и получает от неё файлы пакета …

владелец: [файл 2-lyudi.json]
бот:      Часть «люди» за 29.09 принята. Утро: 19 · Итоги: 18.
          Предупреждения: 1 — нет записей: Кира В.
          Не хватает части «день»: без неё публикация недоступна.

владелец: [файл 1-den.json]
бот:      Часть «день» за 29.09 принята. «Горы, парки и первые тексты»
          Событий: 7 · Достижений: 2 · Задание: сдали 14
          Заметки нейросети: 1
          — Итог без подписи в 20:54 отнесён к Асе К. по содержанию — проверьте.
          Готово к публикации: день, люди.
          [Опубликовать] [Отмена]

владелец: нажимает «Опубликовать»
бот:      Опубликовано: отчёт за 29.09. <ссылка на день>
```

Файлы можно отправить и архивом — бот разберёт все части из него. Текстом отчёт тоже принимается, но предел сообщения Telegram — 4096 знаков, поэтому основной способ — файлы.

**Через админку** — страница «Отчёты дня → Загрузить отчёт»:

1. Выбрать один или несколько файлов либо вставить текст. Нажать «Проверить».
2. Сайт показывает сводку по каждой части: день, что принято, предупреждения, заметки нейросети, а при ошибках — их список.
3. «Опубликовать» публикует черновик дня; «Сохранить как черновик» оставляет его неопубликованным.

В обоих способах при ошибках часть не сохраняется. Опубликованный отчёт можно снять с публикации или заменить новым — в админке.

## 9. Неделя словами: формат `nash-den.week` (секция 39)

Короткая летопись недели голосом командного диктора. Пишется по **уже опубликованным** дням недели, а не по сырому чату: всё, что в неё попадает, уже проверено владельцем.

1. Владелец пишет боту `/week` (текущая неделя) или `/week 3`. Бот присылает архив `nedelya-3.zip`: `00-nedelya.md` — инструкция, состав команды и образец ответа; `nedelya-3.json` — опубликованные дни недели (образ, сводка, факты, цитата, задание, слова дня людей, голоса, инсайты, слова, светлое, проект). Без бота — `manage.py export_week 3`.
2. Нейросеть возвращает один файл JSON.
3. Владелец присылает его боту файлом или загружает на странице «Загрузить отчёт» в админке. Неделя сохраняется черновиком и появляется на сайте только после кнопки «Опубликовать неделю» (в админке — действие «Опубликовать» у «Недель словами»).

```json
{
  "format": "nash-den.week", "version": 1, "week": 2,
  "title": "Неделя, когда нашлась площадка",
  "lead": "Мы начали неделю без площадки, а закончили с двумя живыми вариантами.",
  "sections": [{"heading": "Как шла неделя", "text": "Вторник — «Горы, парки и первые тексты»…"}],
  "voices": [{"member": "mark_o", "text": "Поддержка — это круто", "day": "2026-09-29"}],
  "next": "В понедельник — встреча в парке.",
  "chat": "необязательно: та же неделя для общего чата",
  "notes": ["сомнения для владельца"]
}
```

Образец — `docs/examples/week-example.json` (совпадает с `src/apps/journal/report/week_example.json`).

| Поле | Обязательно | Правила |
|---|---|---|
| `week` | да | номер недели потока: начавшейся, внутри потока |
| `title` | да | образ недели, 2–6 слов, до 60 знаков |
| `lead` | нет | до 400 знаков |
| `sections` | нет | до 6: `heading` до 60, `text` до 1500; абзацы — с новой строки; пустые разделы отбрасываются |
| `voices` | нет | до 7 разных людей: `member` — ключ, `text` до 200 — дословно, `day` — дата внутри недели |
| `next` | нет | до 400 знаков |
| `chat` | нет | до 3500 знаков, на странице недели — блок «текст для общего чата» |
| `notes` | нет | только владельцу |

Ошибки: не тот `version`; номера недели нет в потоке или неделя не началась; нет `title`; неизвестный человек в `voices`. Предупреждения: обрезка по пределу; дата голоса вне недели (дата отбрасывается); второй голос того же человека (отбрасывается); голос не найден в сообщениях автора за день (или за неделю, если даты нет); неделя уже опубликована или уже был черновик. Новый текст всегда становится черновиком: прежняя опубликованная версия заменяется только после публикации.

На сайте: блок «неделя словами» вверху `/weeks/<n>/` и глава в «Альманахе потока» `/almanac/`.

## 10. Другие файлы владельца в той же личке (секция 39)

- **`result.json` из Telegram Desktop** — история чата в базу. Импорт всех тем сразу с настоящими номерами сообщений, повтор ничего не дублирует, правки обновляются. Авторы узнаются по Telegram ID участника, иначе по однозначному совпадению имени («имена в чате» в админке). Бот отвечает сводкой: период, сколько новых и обновлённых, темы с ролями и неузнанные отправители. После импорта и заполнения `chats.toml` команда `/export` собирает txt по темам и посчитанные «ФАКТЫ», как при боте в группе. Без бота — `manage.py import_chat_export /путь/result.json`.
- **Добавки расписания** — объект `{"events": [...]}` в формате `docs/examples/schedule-example.json`: каждое событие проверяется (ключ до 80 знаков, название, даты ISO, время ЧЧ:ММ, вид и статус из списка) и добавляется с источником `chat`. Отклонённые события названы в ответе. Полная перезагрузка `load_schedule` такие события не удаляет; без бота — `manage.py load_schedule --path файл --merge`.
