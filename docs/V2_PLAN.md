## A3. Дизайн-принципы

- Идея прежняя: «из шума — в ясность». Много воздуха, крупные цифры, один громкий цвет на экран.
- Цвета — **только через токены** из `src/static/css/tokens.css`. Новых «сырых» цветов в CSS, шаблонах и JS нет (после секции 28 это проверяет тест). Цвета для холстов JS берёт из вычисленных CSS-переменных.
- Палитры «мягкая» (по умолчанию), «яркая», «тихая» и (с секции 28) темы «светлая/тёмная/как в системе» должны работать в каждом новом блоке.
- Контраст текста не ниже 4,5:1, крупного (от 24 px или 19 px жирного) — 3:1. Текст на тёплой и лаймовой карточке — `--ink` (решение 033, тест `test_section21a.py`).
- Область нажатия не меньше 44 × 44 px. Фокус виден (`:focus-visible`). Всё доступно с клавиатуры. У значков-кнопок есть `aria-label`, у графиков — текстовое описание.
- Движение: короче 0,6 с (кроме входа и постоянного фона по решению 048); у каждой анимации страховочный таймер; в спокойном режиме и при «меньше движения» — мгновенная смена состояния. Эмодзи в интерфейсе нет.
- Тон текстов — спокойный, без оценок и слов «провал», «нарушил», «отстаёт» (`DESIGN.md`, раздел 8). Штрафы — фактом.
- Русская типографика: неразрывный пробел после коротких слов и перед тире, между числом и единицей (`₽`, `%`, `дн.`); «ёлочки»; `—` с пробелами.

## A4. Среда и подводные камни (проверено на этом проекте)

1. **Docker Desktop может быть не запущен.** Признак — `failed to connect to the docker API`. Запуск: `Start-Process "$env:LOCALAPPDATA\Programs\DockerDesktop\Docker Desktop.exe"`, затем жди `docker info` (до 2 минут) и `.\dev.ps1 up`.
2. **PowerShell 5.1 и stderr Docker.** `docker compose up --build` пишет ход сборки в stderr, PowerShell с `$ErrorActionPreference = "Stop"` считает это ошибкой (`NativeCommandError`). Если `.\dev.ps1 up` падает так при живой сборке — выполни в той же сессии `$ErrorActionPreference = "Continue"` и проверяй `$LASTEXITCODE`, либо выполни команду через Git Bash с `MSYS_NO_PATHCONV=1` (иначе Git Bash превращает `/app/...` в путь Windows).
3. **Кеш статики в браузере.** Сервер разработки отдаёт CSS и JS без `Cache-Control`, браузер держит старые файлы. После правки статики — жёсткая перезагрузка (Ctrl+Shift+R) или `await fetch(url, {cache: "reload"})` перед `location.reload()`.
4. **Неразрывный пробел.** В коде и тестах уже есть U+00A0 (суммы вида `1 500`). Текстовая замена с обычным пробелом не найдёт строку. В Python пиши `" "`, при правке файла ищи по фрагменту без пробелов.
5. **CSP** (`apps/access/csp.py`): скрипты только свои (на входе ещё `telegram.org`), встроенных `<script>` и `<style>` нет, атрибут `style=""` разрешён, `img-src 'self' data:`, `connect-src 'self'`. Картинку для предпросмотра показывай через `data:`-адрес; `blob:` в `img-src` нет.
6. **Продакшен-статика.** В `prod.py` статика собирается с манифестом: относительные импорты модулей (`import … from "./x.js"`) переписываются на имена с хешем. Импортируй модули только литеральными относительными путями, без адресов, собранных в рантайме. Ссылка на несуществующий статический файл в CSS/шаблоне роняет `collectstatic` — это проверяется в секции 38.
7. **Сайт в продакшене — HTTP по IP** (решение 043), это не безопасный контекст. Недоступны `navigator.clipboard.readText`, Web Share с файлами, service worker, установка как приложения, Battery API. Такие возможности только через проверку (`window.isSecureContext && …`) и с запасным путём; функции, которые без них бессмысленны, не делать.
8. **Переходы между страницами.** Пропущенный view-transition отклоняет `transition.ready`. В `motion.js` уже есть `transition.ready.catch(() => {})` — не убирай. В скрытой вкладке браузер пропускает переходы сам.
9. **Скрытая или фоновая вкладка** тормозит `requestAnimationFrame` и анимации. Проверяя появление и движение, держи вкладку видимой; у анимаций должен быть страховочный таймер (так уже сделано в `reveal.js`, `ripple.js`).
10. **Режимы данных.** `.\dev.ps1 demo` и `.\dev.ps1 real` стирают данные команды (перед этим команда пишет копию `before-reset-*.dump`). Защита встроена: если в базе есть невосстановимое — сообщения из Telegram или опубликованные отчёты не из `private/reports/`, — команда печатает сводку и **отказывается** без `--confirm-delete=N`. Правило:
    - запускай без ключа и читай сводку;
    - ключ `--confirm-delete=N` разрешён, только если всё перечисленное в сводке — демо-данные, созданные тобой в этой же секции (так бывает при возврате из демо в `real`);
    - если в сводке настоящие сообщения или отчёты — ничего не стирай, проверки режимов делай **только в изолированном стеке** (A5);
    - секция заканчивается в режиме `real` (19 настоящих людей, опубликованные отчёты из `private/reports/`, свежий снимок таблицы).
11. Тесты не ходят в сеть, `SHEET_URL` и токены в `config/settings/test.py` пустые. `.\dev.ps1 real` выполняет `sync_sheet` — это разрешённый `GET` таблицы.
12. `dev.ps1` — только ASCII. Все файлы — UTF-8 без BOM, LF.

## A5. Изолированный стек для проверок

Нужен, когда проверка меняет режим данных, сутки, код дня или публикует отчёты, а рабочие данные невосстановимы. Файл-переопределение — во временной папке, не в репозитории:

```yaml
services:
  web:
    image: nashden-web
    ports: ["127.0.0.1:8011:8000"]
    environment:
      DJANGO_SETTINGS_MODULE: config.settings.dev
      TELEGRAM_BOT_TOKEN: ""
      TELEGRAM_OWNER_ID: ""
      SHEET_URL: ""
    volumes:
      - ./src:/app/src:ro
      - ./docs/examples:/app/docs/examples:ro
    command: ["python", "/app/src/manage.py", "runserver", "0.0.0.0:8000"]
  bot:
    profiles: ["never"]
```

```powershell
docker compose -p nashden-check -f compose.yaml -f <файл> up -d --no-build --wait db web
docker compose -p nashden-check -f compose.yaml -f <файл> exec web python /app/src/manage.py seed_demo --reset
docker compose -p nashden-check -f compose.yaml -f <файл> down -v
```

Перед `down -v` убедись, что в команде имя изолированного проекта, а не `nash-den`. После секции изолированных стеков не остаётся.

# Часть B. Секции

## Секция 27. Основа: решение владельца, типографика, детали

**Цель.** Тексты сайта набраны по правилам русской типографики, цифры стоят ровно, горизонтальные ленты подсказывают прокрутку, всплывающие строки не теряются, деньги не «докручиваются с нуля».

**Состав работ.**

1. `docs/DECISIONS.md`: запись «057. Решение владельца: план версии 2.0 — 02.10.2026» — секции 27–38 `docs/V2_PLAN.md` одобрены владельцем; для их тем план важнее `PLAN.md`/`DESIGN.md`; правка защищённых документов разрешена только в секции 37. И запись «058. Решение владельца: тексты владельца от 02.10.2026» — список строк из A1.5, они действуют вместо текстов `DESIGN.md`, раздел 8, там, где расходятся (пустое состояние достижений). Тест `apps/web/tests/test_owner_texts.py` проверяет, что каждая строка выводится на своей странице (в демо-данных; пустое состояние — на пустой базе).
2. **Типограф.** Чистая функция `typograph(text: str | None) -> str` в `src/apps/web/typography.py`:
   - неразрывный пробел (U+00A0) после слов из одной-двух букв и частых коротких: `а, в, во, и, к, ко, о, об, обо, от, с, со, у, я, на, по, за, до, из, не, ни, но, да, или` — точный список задай константой, регистр не важен, учитывай начало строки и знаки препинания перед словом;
   - неразрывный пробел перед `—` и `–`, если перед тире пробел;
   - неразрывный пробел перед частицами `же, ли, бы` (они не уходят в начало строки);
   - неразрывный пробел между числом и единицей: `₽, %, ‰, дн., дня, дней, ч, мин, чел., человек` (список — константой);
   - не трогает URL и адреса электронной почты, не вставляет второй пробел, **идемпотентна** (`typograph(typograph(x)) == typograph(x)`), `None` → `""`.
   Фильтр шаблона `typo` в `apps/web/templatetags/ui.py` возвращает обычную строку (автоэкранирование остаётся). Примени его к **выводимым** текстам: образ дня, `lead`, сводка, факты, цитаты, голоса, связи, «на что смотрим», проект за день и на странице проекта, достижения, текст строки человека, расписание, тексты банка. В базе ничего не меняется.
3. **CSS-типографика** (новые правила — в `base.css` или `components.css`):
   - `text-wrap: balance` — заголовки (`.h-display, .h-page, .h-card, .day-title, .quote, .voice__text`);
   - `text-wrap: pretty` — абзацы карточек;
   - `hyphens: auto` для абзацев в узких карточках (на `<html lang="ru">`), `hyphens: manual` для `.num, .metric, .label, .chip, .mono, .person__name`;
   - `font-variant-numeric: tabular-nums` — время в ленте суток, `.meter__value`, `.engagement__value`, `.cols__days`, время в расписании, суммы банка.
4. **Ленты с прокруткой вбок** (`.toc`, `.datestrip`, ряды плашек с `overflow-x`): модуль `static/js/modules/hscroll.js` и класс `.hscroll`. Край, за которым есть содержимое, мягко гаснет (`mask-image` на краю 1.5rem; классы `is-start`, `is-end` по прокрутке и `ResizeObserver`). Лента дат при загрузке прокручена так, что выбранный день по центру (меняй `scrollLeft` ленты, а не прокрутку страницы). В спокойном режиме — без плавной прокрутки.
5. **Очередь всплывающих строк** (`toast.js`): события `nashden:toast` встают в очередь (не больше трёх ожидающих, одинаковые подряд склеиваются), каждая строка видна не меньше 1,6 с; при спокойном движении — без сдвига, только смена текста. API события не меняется.

Новое значение сохраняется.

**Чего не делать.** Не менять тексты по смыслу; не применять типограф к полям ввода, `json_script`, атрибутам `data-*`, `aria-label` с числами для дикторов.

## Секция 28. Смысловые токены и тёмная тема

**Цель.** Цвета сайта описаны смысловыми токенами, и сайт полноценно работает в тёмной теме: страницы, меню, графики, фон, банк, вход.

**Состав работ.**

1. **Смысловой слой токенов** в `tokens.css`, поверх существующих (имена существующих токенов не удалять — их проверяют тесты и используют эталоны):
   - `--fg` — основной текст на странице и бумаге; `--fg-mute` — подписи; `--surface` — карточка; `--surface-edge` — рамка обычной карточки (сейчас `--ink`); `--surface-ink` — тёмная карточка; `--on-ink` — текст на тёмной карточке; `--on-ink-mute` — подписи там же; `--track` — пустая дорожка полос (сейчас `--line`); `--page` — уже есть, фон страницы по времени суток; `--focus` — кольцо фокуса (сейчас `--blue`).
   - `--ink` по-прежнему значит «фирменный чёрный»: текст на тёплой и лаймовой карточке, заливки. Не используй `--ink` как «цвет текста на странице» — для этого `--fg`.
2. **Прочёсывание.** Все сырые цвета в `src/static/css/*.css` (`#fff`, `#AAA`, `#8A8A92`, `#9A9AA0`, `#B5B5BA`, `#33333A`, `#2A2A30`, `#DCD9CF`, `rgba(…)` и т. п.), в атрибутах `style=""` шаблонов (`color:var(--ink)` для текста на странице → `var(--fg)`) и в JS-холстах (`fx.js`, `ambient.js`, график человека) переведи на токены. Исключения — только в списке теста (образцы палитр в меню `.swatch--*`, файлы бренда). Составь таблицу «было → стало» в отчёте.
3. **Тема в меню**: группа «тема» — «светлая / тёмная / как в системе» (`theme`: `light | dark | auto`, по умолчанию `auto`). `prefs.js` (`CHOICES`, `DEFAULTS`), `early.js` (до отрисовки ставит `data-theme` = итоговая тема с учётом `prefers-color-scheme`, слушает его смену при `auto`). Мета `theme-color` обновляется скриптом под тему.
4. **Значения тёмной темы** (`html[data-theme="dark"]`) — ориентир, финальные подбери по контрасту:
   - страница `#111113`, вечер и ночь — оттенки чуть теплее/холоднее; карточка `#1A1A1E`; рамка карточки `#34343B`; текст `#F2F0EA`; подписи `#A4A4AB`; дорожка `#2C2C32`;
   - тёмная карточка (`card--ink`) — глубже страницы (`#070708`) с рамкой `#2C2C32`, чтобы читалась как «панель»;
   - тёплая, лаймовая, синяя карточки — цветные заливки, приглушённые под тёмный фон, **текст на тёплой и лаймовой — `--ink`** (решение 033), на синей — светлый; контраст ≥ 4,5:1;
   - палитры «мягкая/яркая/тихая» работают и в тёмной теме (сочетание `data-theme` + `data-palette`).
5. **Бренд.** Знак `mark.svg` (оранжевый) на тёмной шапке читается — его не менять (как на экране входа, `PLAN.md` A9.1). Слово «наш день» — текст `--fg`. Страницы 403/404/500 с полным логотипом (чёрная надпись) **всегда светлые**: принудительно `data-theme="light"` на них.
6. **Холсты.** `ambient.js` берёт цвет линий из `--fg` (не `--ink`); в тёмной теме свечение комет и звёзд рисуется с `globalCompositeOperation = "lighter"`, альфы подобраны так, чтобы фон оставался приглушённым. Перечитывание цветов — по событию смены темы и палитры (`onPrefs` + смена `prefers-color-scheme`). `fx.js` и график человека — из токенов.
7. Экран входа остаётся тёмным в обеих темах (как сейчас).
8. **Тест-страж** `apps/web/tests/test_tokens.py`: (а) в CSS вне `tokens.css` нет шестнадцатеричных цветов и `rgb(`/`rgba(` с числами, кроме разрешённого списка; (б) парсер `tokens.css` в тесте вычисляет контраст пар для светлой и тёмной темы и каждой палитры: `--fg`/`--surface`, `--fg-mute`/`--surface`, `--fg`/`--page`, `--on-ink`/`--surface-ink`, `--ink`/`--hot-fill`, `--ink`/`--lime-fill`, светлая подпись/`--blue-fill` — все ≥ 4,5.

**Чего не делать.** Не менять разметку страниц ради темы, если хватает токенов; не вводить новые шрифты; не перекрашивать логотип; не трогать `docs/design/reference/`.

**Тесты.** Страж из п. 8; меню содержит `name="theme"` с тремя значениями; страницы ошибок содержат `data-theme="light"`.

**Готово, когда.** Все страницы (главная, команда, человек, день, все дни, проект, статистика, меню, всплывающие строки, «все на связи», 404) в тёмной теме без белых «дыр», нечитаемых подписей и потерянных рамок — проверено глазами на 390 и 1280 в демо и настоящих данных; переключение темы в меню и смена системной темы при «как в системе» меняют вид без перезагрузки и без мигания при загрузке; `.\dev.ps1 check` зелёный.

## Секция 30. Банк штрафов 2.0: прогноз, виды, путь к порогу

**Цель.** Банк штрафов помогает команде видеть, куда она движется: прогноз порога, из чего складываются штрафы, неделя к неделе, чистые дни, предупреждение у порога, график накопления.

**Расчёты** — чистые функции в новом модуле `src/apps/web/fines.py` (вход — список дней из `fine_days()`/снимка и настройки; без запросов к базе внутри):

1. **Прогноз** `fines_forecast(days, total, threshold, today, stream_end)`: средний штраф в день за последние 7 календарных дней потока **не позже сегодня** (дни снимка с нулём считаются, будущие даты снимка — нет). Если среднее 0 — «за последние 7 дней штрафов не было, порог не приближается». Иначе — дней до порога `ceil((threshold − total) / среднее)` и дата; если дата позже конца потока — «при нынешнем темпе до конца потока порог не будет пройден». После порога прогноза нет.
2. **Виды** `fines_by_kind(days, start, end)`: суммы по видам (название вида — как в таблице, сравнение без регистра и пробелов), не больше 4 видов + «другое»; по неделям потока (`week_bounds`).
3. **Неделя к неделе**: сумма текущей недели потока и прошлой, разница — фактом («на этой неделе 400 ₽, на прошлой 1 000 ₽»).
4. **Чистые дни**: дни потока не позже сегодня, которые есть в снимке, с суммой 0.
5. **Накопление** `fines_path(days, threshold)`: точки для SVG (сервер считает координаты, как график человека `apps/web/chart.py`) — накопленная сумма по дням и горизонтальная линия порога; текстовое описание для дикторов.

**Вид.**

- Главная (`#bank`): к предохранителю добавить строку прогноза, «чистых дней: N из M», неделю к неделе. При ≥ 80 % порога — класс `.fines.is-near`: плашка ставки «скоро ×10», строка «до повышения ставки осталось … ₽». Карточка не должна стать длиннее «расписания» рядом больше чем на ~20 % на 1280 px — лишнее уходит в статистику.
- Статистика (`#fines`): предохранитель; график «путь к порогу» (SVG, линия порога пунктиром оранжевым, последняя точка подписана); полоса из сегментов по видам за всё время и по неделям с легендой; список дней, где чистые дни показаны приглушённой строкой «без штрафов».
- Цвета сегментов — токены (например, `--hot-edge`, `--ink`/`--fg`, `--lime-bar`, `--fg-mute`), различимы в обеих темах и всех палитрах; сегменты подписаны в легенде и в `aria-label`.
- Тексты — фактом, без оценок; в `DECISIONS.md` запиши новые формулировки.

**Чего не делать.** Таблицу не писать, новых вкладок не читать, сумму банка по-прежнему брать из снимка (строка «Банк», иначе сумма дней).

**Тесты.** Каждая функция `fines.py` на вымышленных данных: прогноз (обычный, нулевой темп, дальше конца потока, после порога, будущие нули не считаются); виды (склейка регистра, «другое»); неделя к неделе; чистые дни; путь (координаты монотонны, порог). Разметка главной (`is-near` при 85 %), статистики (график и легенда). Без снимка — блоков нет.

**Готово, когда.** В настоящих данных главная и `/stats/#fines` показывают прогноз, виды, чистые дни; при подменённом в тесте снимке на 85 % — предупреждение; обе темы и три палитры читаются; `.\dev.ps1 check` зелёный.

## Секция 34. Меню, движение, переходы, пустые состояния

**Цель.** Меню и движение доведены до уровня хорошего приложения: живые превью, удобный лист на телефоне, бережный режим, плавные переходы.

**Состав работ.**

1. **Превью сцен** в группе «фон»: вместо значков — маленькие нарисованные SVG-миниатюры каждой сцены (лучи, потоки, волны, точки) в токенах текущей палитры и темы; «авто» показывает миниатюру текущей сцены и подпись.
2. **Лист меню на телефоне:** фокус не уходит из открытого листа (Tab по кругу), закрытие смахиванием вниз за ручку или шапку (порог ~80 px или быстрое движение; лист едет за пальцем), страница под листом не прокручивается (блокировка прокрутки без скачка ширины). На компьютере поведение прежнее.
3. **Бережный режим:** если `navigator.connection?.saveData` или слабое устройство (`hardwareConcurrency ≤ 4` или `deviceMemory ≤ 2`) и пользователь сам не выбирал силу фона — фон «тихо» и подпись в меню «фон приглушён для экономии». `prefers-reduced-transparency` — подложка меню без прозрачности.
4. **Переход аватара:** при переходе со строки или лица человека на его страницу аватар перетекает на место фото в шапке (имя уже перетекает — `view-transition-name: name-<slug>`). Имя перехода ставится только на нажатый элемент (запомнить `slug` в `sessionStorage` по нажатию, поставить имя в `pageswap` на старой странице и в `pagereveal` на новой), чтобы не было повторяющихся имён. В спокойном режиме — без перехода.
5. **Пустые состояния** (`components/empty.html`): тонкий линейный рисунок «горизонт» (свой SVG, не логотип). Фразы пустых состояний **не менять**: каждое сохраняет свой текст как есть сейчас (в том числе текст владельца у достижений, A1.5).
6. Вибрация `navigator.vibrate?.(10)` при «все на связи» и переключателях меню — на сенсорных устройствах, не в спокойном режиме.
7. Производительность фона: градиенты, которые не зависят от времени, кешируются до изменения размера или палитры; замер кадров в отчёте (средняя длительность `paint` на 1280 и на эмуляции телефона ×4 замедления CPU — если среда позволяет).

**Тесты.** Разметка превью (по одной миниатюре на сцену); `empty.html` содержит рисунок с `aria-hidden="true"`; JS — по возможности проверка логики бережного режима как чистой функции.

**Готово, когда.** Лист меню закрывается смахиванием, фокус заперт, прокрутка страницы не скачет; аватар перетекает в Chrome/Edge; при `saveData` фон тихий; `.\dev.ps1 check` зелёный.

## Секция 35. Поиск по дням и страница недели

**Цель.** Любое слово из отчётов находится за секунду, а неделя видна одним экраном.

**Поиск.**

1. Селектор `search_days(query: str, limit: int = 30) -> list[dict]` в `src/apps/web/search.py`. Данных мало (≤ 63 отчёта потока), поэтому: **один** запрос за опубликованными отчётами потока (`payload`, `day`) и один — за записями людей (`report`/`admin`) с коротким именем; поиск в Python. Нормализация: регистр, `ё → е`, лишние пробелы; минимум 2 символа, максимум 80. Источники и подписи блока: образ дня, сводка, факты, цитата, голоса, связи, «на что смотрим», проект, записи людей (имя · утро/итог). Ранжирование: совпадение в образе дня и сводке выше, затем по дате (новые сверху). Отрывок ±60 символов вокруг совпадения, экранирован, совпадение в `<mark class="hl">` (собирать безопасно: экранировать части, потом оборачивать).
2. `GET /api/search/?q=` — JSON `{query, results: [{date, label, block, snippet, url}]}`, `url` с якорем блока на странице дня. Закрыт шлюзом как `/api/pulse/` (401 для JSON). Пустой или короткий запрос — пустой список.

Нативный `<dialog>`: поле, подсказка «ищите по словам из отчётов», результаты по дням, ↑/↓/Enter, Esc; задержка 180 мс, `AbortController`; состояния «пусто», «ничего не нашлось», «ошибка сети», «новый день — войдите снова» (401). Последние 5 запросов — в `localStorage`. На телефоне окно на весь экран. Модуль `static/js/modules/search.js`.

**Неделя.**

4. `/weeks/` — текущая неделя потока (вне потока — ближайшая не позже сегодня, до начала — пустое состояние); `/weeks/<n>/` для `1…N`, будущие недели — 404. Заголовок «Неделя 2 · 28.09 — 04.10», навигация по неделям как у дней (компонент из секции 31, свайп).
5. Блоки (каждый — только если есть данные): дни недели с образом дня и ссылкой; утро и итог в среднем за неделю; доля закрытых итогов; штрафы недели и чистые дни (функции секции 30); достижения недели; до 6 голосов и цитат из отчётов недели; подвижки проекта недели; из таблицы — сколько человек заполнили план и итоги недели («планы недели: 12 из 19»).
6. Ссылки: подписи недель в календаре `/days/all/`, строка «по неделям» на странице дня, блок в статистике.
7. Запросы к базе страницы недели не растут с числом людей и дней (тест).

**Тесты.** `search_days` (нормализация «ё», регистр, источники, ранжирование, экранирование `<script>` в отрывке, лимит, короткий запрос); `/api/search/` с шлюзом (401) и без; число запросов поиска постоянно; страница недели: границы, 404 будущей недели, блоки при пустых данных, число запросов.

**Готово, когда.** В настоящих данных поиск находит слово из отчёта 29.09 и ведёт к блоку; Ctrl+K и `/` открывают окно, клавиатура работает; страница текущей недели цельная на 390 и 1280 в обеих темах; `.\dev.ps1 check` зелёный.
