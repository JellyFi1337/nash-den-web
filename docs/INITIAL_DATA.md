# Первые настоящие данные

В папке `private/` в корне проекта лежат настоящие данные команды. Папка в git и в образ Docker не попадает, в контейнеры `web` и `bot` монтируется только для чтения как `/app/private`.

| Файл | Что в нём |
|---|---|
| `private/team.json` | 19 человек (14 участников и 5 кураторов): полное и короткое имя, роль, имя пользователя Telegram (где известно), псевдонимы из чата, порядок, по три цели потока; даты потока; проект |
| `private/reports/2026-09-28.json` | отчёт дня за 28.09.2026 — пакет `nash-den.report` версии 2: части `den`, `lyudi`, `proekt` |
| `private/reports/2026-09-29.json` | отчёт дня за 29.09.2026: части `den`, `lyudi`, `proekt`, `golosa` |
| `private/reports/2026-09-30.json` | отчёт за 30.09.2026: все пять частей |
| `private/reports/2026-10-01.json` | отчёт за 01.10.2026: все пять частей |

Каждый отчёт — один файл со всеми частями (объект `parts`, `docs/REPORT_FORMAT.md`, раздел 2). Людей отчёты называют полным именем («Фамилия Имя») — формат это допускает.

## Полнота отчётов

Сводки за 28.09 и 29.09 появились до бота. На 02.10.2026 в папке четыре пакета: первые два содержат три и четыре части, следующие два — все пять. Загрузка с --reports обрабатывает все найденные JSON-файлы, а не только первые дни.

Для публикации обязательны den и lyudi; остальные части и необязательные поля могут отсутствовать. Пустые блоки не показываются. Наличие бота само по себе не гарантирует заполнение целей, контрактов, достижений или голосов: они зависят от опубликованного пакета. Полный вымышленный образец — docs/examples/report-example.json. Отчёты не создают RawMessage; историю сообщений импортируют отдельно.

## Формат `team.json`

```json
{
  "stream": {"start": "2026-09-21", "end": "2026-11-22"},
  "project": {"title": "…", "tagline": "…", "target_date": "2026-10-23"},
  "members": [
    {
      "full_name": "Фамилия Имя",
      "short_name": "Имя",
      "role": "participant",
      "telegram_username": "",
      "aliases": ["имя в чате"],
      "sort_order": 1,
      "goals": [{"kind": "breakthrough", "title": "…", "deadline": "2026-11-17"}]
    }
  ]
}
```

Цели в `team.json` — снимок на 30.09.2026. Источник истины по целям — таблица команды (`docs/SHEET.md`): после первой синхронизации их обновляет `sync_sheet`.

## Режимы данных

Настоящие и вымышленные данные в одной базе не смешиваются (`docs/PLAN.md`, A4.1). Переключение очищает данные команды, в том числе «Недели словами». Сначала сводка и копия; при невосстановимых сообщениях/отчётах команда отказывается без точного --confirm-delete=N. Сообщения, загруженные из `result.json`, хранят настоящие номера Telegram и тоже считаются невосстановимыми: держите исходную выгрузку, чтобы загрузить её снова после сброса. Агент подтверждает только свои временные демо-данные; настоящие накопленные данные сохраняются, проверки — в PLAN A5. Команды:

- `.\dev.ps1 real` — очистить данные команды, загрузить `team.json`, опубликовать все файлы отчётов из private/reports/, перенести роли тем из `private/chats.toml`, обновить снимок таблицы;
- `.\dev.ps1 demo` — очистить данные команды и создать вымышленные.

## Команда загрузки

`manage.py load_private [--reports]`

- Без ключа: создаёт или обновляет людей (ключ — `full_name`), их цели, псевдонимы, даты потока в `SiteConfig`, название и срок проекта. Повторный запуск ничего не дублирует. Привязки Telegram и фото, уже внесённые в админке, не затирает; имя пользователя Telegram заполняет, только если поле пустое.
- С ключом `--reports`: дополнительно проверяет и публикует каждый файл из `private/reports/` через `validate_report` и `publish_report`, по возрастанию даты. При ошибках проверки печатает их и отчёт не публикует.
- Если в базе есть демо-люди, команда отказывается и предлагает `--reset` (A4.1).
- Если папки `/app/private` нет, команда сообщает об этом и завершается без ошибки.

## Как этим пользуется агент

1. **Проверка формата.** Оба отчёта — настоящие образцы формата. Функция `validate_report` должна принимать их без ошибок. Если отчёт не проходит проверку — это повод сверить код с `docs/REPORT_FORMAT.md`, а не править файлы в `private/`.
2. **Проверка страниц.** Смотри уже загруженные настоящие данные; дополнительный импорт и смену режимов проверяй в отдельном стеке по PLAN A5. Смотри оба дня: на 28.09 нет «Голосов дня» и связей, на 29.09 у одного человека нет итога.
3. **Полный набор блоков.** Вымышленный образец `docs/examples/report-example.json` публикуй только на вымышленных людях в отдельном стеке по PLAN A5, без настоящего бота и внешних настроек. Рабочую real-базу не меняй.
4. **Локальный тест.** В репозитории есть тест, который проверяет все файлы `private/reports/*.json` и пропускается, если папки нет. Он читает файлы с диска и не содержит их текста.

## Чего нельзя

- Копировать имена, цитаты и тексты из `private/` в код, тесты, фикстуры, документацию, сообщения коммитов и отчёты в чате. В отчёте секции допустимы только числа: сколько людей, записей, предупреждений.
- Изменять файлы в `private/`.
- Добавлять `private/` в образ Docker: папка должна быть и в `.dockerignore`.
- Тесты в репозитории остаются на вымышленных данных (`docs/examples/`, фабрики).

## Что проверить владельцу

- Имена пользователей Telegram в `team.json` взяты из таблицы команды и упоминаний в чате и не проверены. Сверьте их по ответу бота на `/people`.
- У семи человек имени пользователя нет — их бот привяжет после ручного ввода в админке.
- В отчёте за 29.09 время итога одного человека указано приблизительно; у одного человека итога нет. Это перечислено в поле `notes` отчёта.
- В таблице команды на вкладке с целями есть два человека, которых нет в `team.json`. Если они в команде — добавьте их в админке; иначе синхронизация покажет их в списке несопоставленных.
- В «Банке штрафов» три строки подписаны только именем, которое есть у двух людей. Чтобы штрафы этих людей появились на сайте, попросите кураторов написать там короткие имена с сайта (поле «короткое имя» в админке).
- Конец потока — 22.11.2026, выпускной по расписанию (решение 036). Цели участников по-прежнему сформулированы «к 17 ноября»: сроки целей и конец потока — разные даты.
